    21	# Process: PO output check
    22	
    23	**Purpose:** Check a piece of the PO role's output against the PM
    24	role's framing under criteria the definitions state, so that the PM
    25	role decides from a screen verdict — pass, fail with the criterion
    26	named, or a definition change — and never by reading every artifact.
    27	
    28	**Guiding statement:** The check is the criteria applied, not the
    29	checker's reading. A finding the criteria cannot name is a missing
    30	criterion, and the decision that follows is a definition change, not a
    31	verdict on the maker.
    32	
    33	**Outcomes:**
    34	- O1. The output is screened against a named criteria set and the
    35	  framing it claims to serve — witnessed by `screen`'s inputs and the
    36	  `screen-review` it returns.
    37	- O2. The PM role decides from the review and round log; the artifact
    38	  reaches the decider only through the findings' quotes — witnessed by
    39	  `decide`'s inputs, which exclude the artifact.
    40	- O3. Every screen round is recorded and the loop exits on a clean
    41	  verdict, on findings no criterion names, or at the round cap —
    42	  witnessed by `log-round` and `route-screen`.
    43	- O4. A fail names the criterion missed; a definition change names the
    44	  gap, and the gap is filed in the named definition's Document History
    45	  — witnessed by the `check-decision` fields and `record`'s
    46	  `gap_entry` output.
    47	- O5. A question the framing cannot answer leaves the run as an ask to
    48	  the PM role, with a default, and the run resumes — witnessed by
    49	  `revise`'s `asks` and the `ask` value.
    50	
    51	**Roles:** maker — [`../roles/lead-po.md`](../roles/lead-po.md)
    52	(submits and revises; never decides its own pass). screener —
    53	[`../roles/cold-reviewer.md`](../roles/cold-reviewer.md) (fresh
    54	context every round; judges against the criteria). the PM role —
    55	[`../roles/lead-pm.md`](../roles/lead-pm.md) (accountable for the
    56	decision; a human-held role that decides from the verdict; its
    57	assisting agent prepares the record and the gap entry).

    60	[`../skills/po-output-check/SKILL.md`](../skills/po-output-check/SKILL.md)

   120	start: screen
   121	parameters: [artifact, framing, criteria_path]
   122	result: decision
   123	steps:
   124	  - id: screen
   125	    name: Screen against the criteria
   126	    run-by: {role: cold-reviewer, execution: agent, fresh-context: true}
   127	    inputs: [artifact, framing, criteria_path]
   128	    outputs: [review]
   129	    prompt: |
   130	      Read the criteria set at criteria_path, the framing at framing,
   131	      and the artifact at artifact — nothing else. Judge the artifact
   132	      against every criterion and against the framing: does each part
   133	      of it trace to the framing, and does anything in it serve no
   134	      framed outcome? Report every finding with the criterion it fails
   135	      by name, the quoted text, the change, and whether you could
   136	      decide it (confident) or not (wobbly). A defect no criterion
   137	      names is a finding with criterion "uncovered". Verdict "clean"
   138	      only if there are no findings; otherwise "findings" with the top
   139	      three changes.
   140	    next: log-round
   141	    annotations:
   142	      fabro: {model: high-reasoning, node: separate-context-per-round}
   143	
   144	  - id: log-round
   145	    name: Record the round
   146	    run-by: {execution: runtime}
   147	    inputs: [review, round_log]
   148	    set:
   149	      round_log: round_log + [review]
   150	    next: route-screen
   151	
   152	  - id: route-screen
   153	    name: Route on the screen
   154	    run-by: {execution: runtime}
   155	    inputs: [review, round, round_cap]
   156	    branches:
   157	      - label: "success exit: clean"
   158	        when: review.verdict == "clean"
   159	        next: decide
   160	      - label: "definition exit: every finding is uncovered — nothing the maker can repair"
   161	        when: review.findings.all(f, f.criterion == "uncovered")
   162	        next: decide
   163	      - label: "failsafe exit: round >= round_cap — decide with findings open"
   164	        when: round >= round_cap
   165	        next: decide
   166	      - else: revise
   167	
   168	  - id: revise
   169	    name: Revise the output
   170	    run-by: {role: lead-po, execution: agent}
   171	    inputs: [artifact, review, framing, ask]
   172	    outputs: [artifact]
   173	    asks: [lead-pm]
   174	    prompt: |
   175	      Repair every finding whose criterion is named; leave findings
   176	      marked "uncovered" as they are — they are the PM role's to
   177	      decide. If a repair needs something the framing does not say —
   178	      the originator's intent, whether a thing is in scope, a decision
   179	      another role's domain holds — return an ask to lead-pm instead
   180	      of guessing: the question, its kind, the default you will apply
   181	      if unanswered, and a checkpoint holding the repairs made so far.
   182	      On the first pass ask is empty; if it carries an answer or
   183	      resolved defaulted, act on it and finish the repairs.
   184	    next: advance-round
   185	
   186	  - id: advance-round
   187	    name: Advance the round
   188	    run-by: {execution: runtime}
   189	    inputs: [round]
   190	    set:
   191	      round: round + 1
   192	    next: screen
   193	
   194	  - id: decide
   195	    name: Decide on the verdict
   196	    run-by: {role: lead-pm, execution: human}
   197	    inputs: [review, round_log, framing]
   198	    outputs: [decision]
   199	    prompt: |
   200	      From the final review and the round log, decide. "pass": the
   201	      screen is clean, or its only findings are uncovered and you judge
   202	      none of them needs a criterion — say so in the reasons. "fail": a
   203	      named criterion is still missed at the round cap — name it.
   204	      "definition-change": an uncovered finding should have been a
   205	      criterion, or a criterion the output met produced something that
   206	      does not serve the framing — name the definition and what it
   207	      lacks. Decide from the quotes in the review; open the artifact
   208	      only for a finding marked wobbly. Record your reasons.
   209	    next: record
   210	
   211	  - id: record
   212	    name: Record the decision
   213	    run-by: {role: lead-pm, execution: agent}
   214	    inputs: [decision, artifact, round_log]
   215	    outputs: [artifact, gap_entry]
   216	    prompt: |
   217	      Write into the artifact's Document History one review entry per
   218	      round with its verdict, then a state entry carrying the decision
   219	      and its reasons. Set the artifact's status — "checked" on pass,
   220	      "returned" on fail with the criterion named, "pending-definition"
   221	      on definition-change; these three values are this process's
   222	      until the artifact typedefs define their own. On
   223	      "definition-change", write a review entry into the Document
   224	      History of the definition the decision names, stating the gap,
   225	      and return that entry's text as gap_entry; otherwise return
   226	      gap_entry empty. Return the artifact.
   227	    next: end
   228	```

     1	# Cold-read screen: po-output-check (process-definition v1) + check-decision (v1) — round 1
     2	
     3	**Verdict: findings.** Compiles and renders correctly, both loops carry labeled exits, and the ask clauses conform to typedef v4. The defects are in the *logic* of the check: an "uncovered" finding can never clear the screen and is never repaired, so it burns every round to the cap before the PM sees it — the opposite of the guiding statement; the `review` type has no per-finding "wobbly" or "uncovered" field the prompts rely on; two prompts write to undeclared channels; and one route-decision branch is dead by the decide prompt.
     4	
     5	## Required changes, most important first
     6	
     7	**1. The "uncovered" path defeats its own purpose (screen prompt, revise prompt, route-screen).**
     8	Screen: `Verdict "clean" only if every criterion holds and nothing is uncovered`. Revise: `For a finding marked "uncovered", leave the text and note it for the decider.` Route-screen exits only on `review.verdict == "clean"` or `round >= round_cap`. Trace: an uncovered finding → verdict "findings" → revise leaves it → advance → screen reports it again → repeat until the cap. The guiding statement says an uncovered finding "is a missing criterion, and the decision that follows is a definition change" — yet the process makes the PM wait three rounds to make it, and the maker spends two rounds repairing nothing. Repair: either add a labeled exit on route-screen for "findings but every finding uncovered" → decide, or let the screen return "clean" when only uncovered findings remain and carry them separately (see 2). Also: decide's prompt has no verdict for an uncovered finding the PM judges *not* worth a criterion ("you judge should have been a criterion" — and if not? neither pass — "nothing uncovered remains" — nor fail nor definition-change fits).
     9	
    10	**2. The `review` type does not carry what the prompts read from it.** `review` (v2) has `verdict`, `stumbles`, `unintroduced_terms`, `ask_decidability` (an unkeyed array of confident/wobbly/cannot-decide, built for a presentation's asks), `top_changes`. The screen prompt asks for "every finding with the criterion it fails and the quoted text" and a category "uncovered"; the decide prompt reads "a finding the review marks wobbly". No field holds a finding, its criterion, an "uncovered" mark, or a per-finding decidability. The screen is asked for output the type lacks, and O2's "opening the artifact only where a finding is wobbly" has nothing to witness. Repair: either a `screen-review` type (findings: [{criterion|uncovered, quote, decidability}]) or an extension of `review` — with the screen prompt telling the screener to mark decidability per finding, which it currently does not.
    11	
    12	**3. Undeclared outputs (guideline rule 4 / scenario 4).** Revise: "note it for the decider" — revise's outputs are `[artifact]`; the note has no declared home (and the decider reads `review`, `round_log`, not the maker's notes). Record: "file the gap against the definition named, as an update to that definition's owner's queue" — no output, no data value, and "owner's queue" is undefined anywhere in the read set. O4 claims this filing is "witnessed by … `record`", but nothing in `record`'s outputs shows it happened. Repair: declare the filed gap as an output (or a `run` that writes it) and name the queue, or drop the claim from O4.
    13	
    14	**4. `artifact_type` is loaded and never used.** Declared as a parameter, input to `screen` and `decide`; neither prompt mentions it, no check or branch reads it. Under `least-context` an input with no reference is a defect. Either the screen selects the criteria set from it (then `criteria_path` is redundant) or it goes.
    15	
    16	**5. `route-decision`'s `else` branch is dead by construction.** Decide is reached only via `clean` or `round >= round_cap`. On a clean screen the prompt allows only "pass" or "definition-change" ("fail" is defined solely "at the round cap"); at the cap, row 2 (`round >= round_cap`) catches "fail" before `else`. `else` therefore fires only if the human returns a verdict the prompt forbids — and then sends the run to `revise` without passing `decision`, so the PM's reason is lost. Either delete the row (and make `else: record` the cap case) or define an early-fail path deliberately with `decision` in revise's inputs. The loop is bounded either way (advance-round still increments), so scenario 3 passes; this is a routing defect, not an exit defect.
    17
