## Outcome

**Mode: shaping** (intent-012 → a shaped candidate). Terminal artifact reached:
`cand-010` driven to `shaped`, validated (`shop-knowledge validate` conforming),
coherence gate green, provenance edge to `intent-012` materialized both directions.

**The forks were resolved by the product authority, in-session, against my
recommendations — and the shape improved through two corrections:**

1. **First bet = the FIND half, not the record-form skill.** The authority named
   the two limiting things as tool + artifact-metadata quality, then artifact
   content quality, and directed: "deal with this inability to find relevant
   documents easily first." So the (b)/complete+correct-selection half of the
   proven decomposition leads; the (a)/record-form/inspection half becomes the
   next bet.

2. **Spine = tags (spine A), populated by inference — not semantic search.** Of
   the three named mechanisms (tagging, per-doc inference relevance, semantic
   search), the authority put tagging first ("the single biggest gap right up
   front"). Reconciled against verifiable grounding's demands: no single mechanism
   gives both reproducibility and completeness, so the shape is a reproducible tag
   spine + an inference completeness sweep (which doubles as the tag-population
   bootstrap engine). Semantic search is the follow-on upgrade.

3. **Deliverable = a composition, not a monolith (two corrections).** My first
   framing ("fix `--help`") was corrected: the answer to wasteful runtime tool-
   rediscovery is that usage lives in a *loaded skill*, not a prettier help. My
   second framing ("one find-entry-points skill") was corrected: it is a *group*
   of thin atomic command-skills that each just run one corpus command, *combined*
   into a composite — decompose then combine. cand-010 is shaped as that vertical
   slice (a few atoms + one composite), with the full atomic-skill / operational-
   skills library named as the follow-on program.

**Prior art reconciled.** cand-010 succeeds `cand-003`'s knowledge-corpus element:
cand-003's open "does shop-knowledge expose a query interface?" rabbit hole is
discharged by this session's empirical finding, and its "the tool already gets it
right" premise is disproven for the knowledge corpus by the 5-round experiment.
cand-003's separate scenario-corpus element is untouched.

**Dogfooded grounding (empirical, this session).** Against the live corpus via
`shop-knowledge`: **0 of 153** artifacts carry non-empty `tags` (the `tag` facet
exists per ADR-067 but has nothing to query); `query` returns clean L0 JSON but
`--help` returns an error string and **exits 0** (a caller cannot detect the
failure) — the concrete warrant for the "populate tags" and "usage-in-a-skill"
elements of the shape.
