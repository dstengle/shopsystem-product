### The comparison

On the measures that compare like for like — wall minutes per
feature, agent steps per feature, where the coordination sits, feature

### Why the information was lost

The feature contract (feat-run-measurement) names "the harness's usage
report" and defines it nowhere. The form lived only in the cost-row
tool's parser, copied from one haiku run (lead-5wzgl). The router-usage
change (router v10) named no form and was verified by a rendering
check, not a row. The harness's report changed shape between
2026-09-08 and 09-09, with no description beside it. The authority's
words: "The detail of execution cost changed between tool
implementations, so there was not a good contract in place."

### The contract, made

req-2026-09-09-usage-report-shape through intake and the lane on the
router (lead-st6wo, lead-ctl8c), two rounds: the router definition
(v12) now names the exact `step` and `usage` comment forms, the usage
report as a data type (nothing per turn to the router; to the starter
at end, one tokens figure with tool uses and duration per agent step),
and the starter's `report` comment form; the run-cost typedef (v5)
names the row's fields as those forms make available; the tool reads
those two definitions. Round one's check caught a router-whole
figure the definition did not cover; dropped. Verified: the rows on
lead-lv37s carry figures.

### Found at the first rollup

The rollup reads the artifact's columns by position under the
retired names (tokens reported as context, tool uses as output), and
the cost row's minutes span the wrong events. Recorded as
req-2026-09-09-rollup-reads-typedef and run through the lane
(lead-ex5ju, lead-d0er0), done in one round: the rollup reads columns
by name and minutes span a step's own start and completion. The
rollup for init-plain-voice now reads its one artifact's sums
(tokens 192,791, tool uses 47, minutes 9.6 for the authoring); the
other two executions of the feature wait on the next request. A
