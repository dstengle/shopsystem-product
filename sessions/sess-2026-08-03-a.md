## Where the session ended — the trust question

The authority closed on a broader challenge: *"How can we build a whole schema
system and have this happen? How can I trust any of these documents?"*

Answered from verified state. `tags` is **not** mandatory — the required set is
`type, id, title, status, created, updated, authors, description`, and the base
schema pins that an **omitted** `tags` field conforms. So 0/167 was never a
violation; it was designed behavior, which is why it stayed invisible. The
schema validates **shape, not the key space**: an allowlist for required fields
and a no-op otherwise, so any invented key is accepted.

The trust-breaking fact: **ADR-067 D5 declares `distribution` required, 0 of 167
artifacts carry it, and the gate reports zero findings.** An accepted decision
says a field is required, no document has it, and every check passes.

Standing directive recorded (`lead-j7t0j`, P1): **front-matter validation must
be strict — a closed field set that rejects unrecognized keys.** Not shaped, not
dispatched, no vehicle chosen; sequencing matters because strict mode over 169
artifacts surfaces a backlog immediately.
