## Outcome

**Mode: discovery (review of evidence)** on work item lead-rr5c0,
opened on req-2026-09-07-run-efficiency. Converged.

### Evidence under review

The cost analysis of init-tool-skills (in the request): 132 wall
minutes, 171 agent-minutes, about 85M tokens of context processed;
the lead-pm session 64M of it; the builds and the PO's feature prose
the heavy agent steps; screens cheap. Measured on the artifacts:
history is 39–43% of the two features and 82–88% of the initiatives;
the longest history rows run 1,600 words.

### Authority's words (select quotes)

- "We need drastically higher efficiency. This was a relatively
  straightforward task and should not be so expensive."
- "Prose is missing as a top level issue. Much of the text is both
  much too verbose and much too complex for the job at hand. We need
  to define a voice that is straightforward and rejects complexity and
  excessive verbosity and explanation. The least context principle is
  also violated by this unnecessary prose."
- "This should be completely mechanical data gathering that can even
  be executed for each run to support optional analysis."
- "The lead-pm should not be coordinating a running graph at all, not
  just the bookkeeping. This should be a deterministic process that
  can be run by a very cheap and fast model."
- "Are these getting expensive to edit due to the history? Is the
  overall size causing issues for context because history is getting
  read in along with the rest of the artifact?" — both confirmed by
  measurement.
- "We are hitting a fundamental issue with our single-level initiative
  system... We need a sub-initiative type for tracking related things.
  Building a process runner should not be in the appetite of a
  measurement initiative."
- "I prefer subinitiative... one type with parent link... parents
  don't have bets, only children... I'm okay with only having the
  linking one way."
- "I want a request put in to have tools (interfaces) to read and
  write artifacts... context size and editing complexity, as well as
  rendering calculated fields like bi-directional relationships."
- "converge, but make process runner first"

### Decided

- Sub-initiatives: one type, the child names its parent, the parent's
  list derived, no bet on a parent. Made through the lane
  (req-2026-09-07-sub-initiative) before the frame.
- Run efficiency framed as a parent with four sub-initiatives, in
  order: the process runner; measurement at session close; artifact
  tools; the voice (a guideline, and the history entry's form).
