# Initiative: Execution vocabulary

## Framing

Originator (product authority, 2026-09-08; req-2026-09-08-definition-vs-instance, section 1): "we will use the process definition to refer to the definition and we will use 'execution' to represent the instance"; a reference to a definition is its full id (request-intake-process); one execution is execution:request-intake:lead-hf45; "run" is a verb only; "anchor" is the bead.

Problem: nothing in the corpus distinguishes a process definition from one instance of it; run, runner, and anchor each patched that, inconsistently, across 147 files. Outcome: one term, execution, names an instance everywhere; a definition is named by its id; a bead is called a bead; the old terms stand only in superseded artifacts and in "process-runner".

## For whom

Every role and every definition that names an instance; the router first. Measure: artifacts in the basis, the delivered features, and the glossary using run as a noun or anchor for a bead. Now: 147 files. Target: 0, the superseded ones excepted. Interaction types: none.

## Appetite

One working session. No-gos: no edit in place of a delivered artifact — supersede it; no change to what any definition requires.
